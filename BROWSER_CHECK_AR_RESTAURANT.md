# Browser check — AR restaurant menu

Дата проверки: 2026-08-26.

Страница `/ar-restaurant/` открылась локально в Chromium без ошибок навигации. Визуально отобразились тёмная glassmorphism-композиция, камера-заглушка, 3D-модель мясного блюда, информационная карточка, три категории, кнопка запуска AR и кнопка сброса позиции.

Переключение на категорию «Напитки» сработало без перезагрузки: заголовок изменился на `Citrus Spark`, описание и цена обновились, а загруженная модель сменилась на локальный `drink.glb`. Статическая проверка `node --check assets/js/restaurant-ar.js`, компиляция генератора GLB и проверка заголовков всех трёх GLB прошли успешно.

Ограничение smoke-теста: sandbox Chromium не даёт реальный видеопоток камеры по локальному URL без пользовательского разрешения, поэтому pinch-жест и MediaPipe проверяются кодом и требуют финального теста на HTTPS-домене с физической камерой.

Дополнительная проверка: справочный диалог открылся по кнопке `?`, содержит четыре шага и поясняет fallback. После загрузки и смены категории консоль Chromium не показала сообщений об ошибках.

Главная `/` также открылась штатно: новый блок `BROWSER AR EXPERIENCE` отображается между категориями и референсами, ссылка `/ar-restaurant/` присутствует. Существующее cookie-окно сайта осталось без изменений и визуально находится поверх главной, как предусмотрено текущей реализацией.

Автоматический DOM-тест подтвердил fallback-перетаскивание: позиция карточки изменилась с `left: 594px, top: 233.586px` на `left: 859px, top: 272.172px`, после клика reset вернулась в центр. Важно: `model-viewer` обновляет свойство `src` на `/assets/models/restaurant/drink.glb`, но не обязан синхронно отражать его в HTML-атрибуте; проверка свойства `viewer.src` показала правильный drink GLB, `viewer.loaded` — `true`.

Проверка кнопки «Включить AR» в sandbox завершилась ожидаемым fallback: статус сменился на `Камера не запущена`, а интерфейс предложил разрешить доступ или перетаскивать блюдо пальцем. В консоли присутствует только предупреждение `NotFoundError: Requested device not found`, без необработанной ошибки приложения.

Публичная проверка `https://albaspace.com.tr/ar-restaurant/` сразу после push дважды вернула стандартный GitHub Pages `404 File not found`, тогда как локальный сервер отдаёт страницу корректно. Это указывает на ещё не завершившийся или не обновившийся Pages deployment/CDN, а не на ошибку маршрута в репозитории. Следующий шаг — дождаться завершения workflow и повторить live-проверку.

После завершения workflow публичная проверка прошла: `https://albaspace.com.tr/ar-restaurant/` отдаёт HTTP 200 и визуально показывает опубликованный `AR Menu` с 3D-стейком, категориями, кнопками включения AR/reset и privacy note. GitHub Actions `Deploy static site to GitHub Pages` и `CI` для commit `56560e2` завершились успешно.

Проверка многоблюдной структуры: на старте отображается `1 / 2` и стейк. Клик по стрелке «вперёд» переключает на `2 / 2`, `Каре ягнёнка`, новую цену и описание; визуально загружена отдельная модель `lamb-chops.glb`. AR-контроллер и экранная композиция сохранились.

Обновлённый тест: при переходе в «Десерты» индекс сбрасывается на `1 / 2` и показывается `Трио мини-десертов`. Стрелка «вперёд» переключает на `2 / 2`, `Шоколадный торт`, цену `₺ 220` и отдельную модель `chocolate-cake.glb`. Счётчик, aria-label стрелок и status-подсказка обновляются.

Автоматический цикл напитков прошёл успешно: `Citrus Spark` (`1 / 2`, `drink.glb`) → `Alba Latte` (`2 / 2`, `latte.glb`) → циклический возврат к `Citrus Spark` (`1 / 2`). Позиция блюда остаётся центрированной после каждой смены, reset работает, консоль не показала новых ошибок.

После рефакторинга ручной drag fallback сохранился: текущий `Citrus Spark` переместился с `left: 594px, top: 233.586px` на `left: 871px, top: 272.172px`, затем reset вернул позицию в центр.

Live-проверка с `?v=2ff7b30` увидела новые стрелки и счётчик в HTML, но клик по live-стрелке пока не переключил блюдо. Причина — HTML обновился раньше закэшированного `/assets/js/restaurant-ar.js`, поэтому следующим исправлением добавлен version query к JS/CSS asset URL для гарантированного обновления CDN-кэша.

Повторная live-проверка после `4b002ab`: публичный HTML содержит новую разметку стрелок, но пока не содержит версии `?v=4b002ab` на CSS/JS, а live-клик не переключает блюдо. Pages deployment для этого коммита ещё не завершён; после него asset query должен принудительно загрузить новый контроллер.

После завершения нового Pages run live HTML содержит versioned asset URLs и новые стрелки, однако browser-клик по публичной стрелке всё ещё оставил `1 / 2`. Следующая диагностика проверит фактически загруженный script URL и консоль: вероятна кешированная модульная страница/JS в sandbox-браузере, а не ошибка локального контроллера, который уже прошёл DOM-тест.

Диагностика показала, что прежняя вкладка держала старый модульный HTML/JS без query, несмотря на свежий ответ curl. После открытия уникального URL `?v=4b002ab&fresh=1` публичная страница получила новую разметку стрелок и счётчик; теперь проверяется фактический URL свежего контроллера в этой вкладке.

Финальная live-проверка после cache-busting прошла: загружен `https://albaspace.com.tr/assets/js/restaurant-ar.js?v=2ff7b30`; стрелка переключила `Стейк на гриле` (`1 / 2`, `steak.glb`) на `Каре ягнёнка` (`2 / 2`, `lamb-chops.glb`). В live-консоли новых ошибок нет.

Проверка camera-first mobile layout: intro, tracking status, help и privacy-текст скрыты; на экране остаются категории, стрелки, счётчик, название/цена блюда, кнопка `Включить AR` и reset. Локальная стрелка переключила `Стейк на гриле` на `Каре ягнёнка` (`2 / 2`), модель и карточка обновились без прокрутки страницы.

Проверка компактного live-интерфейса после `2ff6908`: публичная страница с `?v=camera-fix-1` скрывает intro/tracking/help/privacy-инструкции, оставляет категории, стрелки, счётчик, цену, `Включить AR` и reset. Live-клик по стрелке переключил стейк на каре ягнёнка (`2 / 2`) без прокрутки.

Для новой итерации проверены официальные API: `MediaRecorder` записывает `MediaStream`, поддерживаемый MIME можно выбирать через `MediaRecorder.isTypeSupported()`, а финальный Blob приходит в `dataavailable` после `stop()` ([MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)). Документация model-viewer подтверждает AR-режимы и параметр `ar-placement`; для настоящей фиксации в физической комнате нужен поддерживаемый WebXR/ARCore/Quick Look путь, тогда как текущий экранный camera overlay должен иметь собственный устойчивый fallback ([model-viewer docs](https://modelviewer.dev/docs/index.html#ar-placement)).

Дополнительная проверка официальных материалов: на ARCore-supported Android `model-viewer` может запускать WebXR или Scene Viewer в зависимости от `ar-modes`; для WebXR DOM-элементы страницы остаются доступны внутри браузерной AR-сессии, тогда как Scene Viewer/Quick Look не получают DOM-контролы ([ARCore model-viewer guide](https://developers.google.com/ar/develop/webxr/model-viewer), [model-viewer AR example](https://modelviewer.dev/examples/augmentedreality/)). Поэтому для привязки к столу нужно включать `ar-placement="floor"` и native AR-путь, а photo/video controls сохранять в экранном camera overlay/fallback.

Проверка новой сцены: локальная модель стартует в центре viewport; светящийся круг и progress-line скрыты. Кнопка UI-toggle переводит экран в чистый режим: все меню/AR-кнопки исчезают, остаются только центральная capture-кнопка и `+` для возврата интерфейса.

Проверка capture/UI: `ui-toggle` скрывает весь `ui-chrome`, `ui-reveal` возвращает его, а центральная capture-кнопка остаётся видимой в чистом режиме. Короткое нажатие в sandbox не ломает DOM; реальный Blob/галерею нужно проверить на телефоне с активной камерой, поскольку sandbox не имеет webcam.

Новая локальная проверка: `dish-card` стартует ровно по центру viewport; `dish-stage::before` и `.dish-grab-ring` имеют `display: none`; capture и native AR кнопки существуют. Переход `Напитки` → следующее блюдо показывает `Alba Latte` (`2 / 2`, `latte.glb`). UI-toggle прячет UI, capture остаётся видимой, ui-reveal возвращает интерфейс.

Проверка новой геометрии: стартовый центр `left: 640px`, крайний drag влево даёт `rectLeft: 0`, крайний drag вправо — `rectRight: 1280`, reset возвращает центр; значит ограничение больше не привязано к правой половине. Console smoke-test не добавил runtime-ошибок.

Capability smoke-test выполнен в Chromium; bridge-консоль не сериализовала объект capabilities, поэтому проверка реального MediaRecorder/мобильного native AR остаётся device-dependent. Код использует стандартные `MediaRecorder`, `canvas.captureStream()` и `model-viewer.toDataURL()`; реальную камеру, системное сохранение и AR-прикрепление требуется проверить на Android/Yandex Browser.

Однозначный browser capability test: `MediaRecorder`, `canvas.captureStream()`, WebM VP9/VP8 и `model-viewer.toDataURL()` доступны; `toDataURL('image/png')` вернул валидный PNG data URL и непустой `image/png` Blob. Native AR API доступен как метод, но в sandbox `canActivateAR` равно `false`, поэтому физическую anchor-сцену нужно проверять на ARCore-телефоне.
