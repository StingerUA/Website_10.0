# AlbaSpace password reset — free setup

The implementation in this branch uses the existing Cloudflare Worker + D1 auth system and Resend only as the outbound email transport.

## What is already implemented

- `POST /auth/forgot-password`
- `POST /auth/reset-password`
- one-time 256-bit reset tokens
- only SHA-256 token hashes are stored in D1
- 30-minute default expiry
- all previous reset links for the account are invalidated when a new one is created
- successful password reset invalidates all existing sessions for the account
- email/account enumeration protection
- IP + email rate limiting
- Turkish, English, and Russian email/UI copy
- forgot-password and reset-password pages for TR/EN/RU

## 1. Create the free Resend account

Create a Resend account and add `albaspace.com.tr` under Domains.

Add the DNS records Resend shows (SPF/DKIM and any ownership record it requests) in Cloudflare DNS. Do not invent the records: copy the exact values shown by Resend, then wait until the domain status becomes verified.

Create an API key with permission to send email.

## 2. Add the Resend API key to the Worker

In Cloudflare Dashboard:

Workers & Pages → `albaspace-api` → Settings → Variables and Secrets → Add

Name:

```text
RESEND_API_KEY
```

Value: the API key generated by Resend.

Save it as a secret/encrypted value. Never commit the value to GitHub.

The non-secret defaults used by the Worker are:

```text
PASSWORD_RESET_TTL_SECONDS=1800
PASSWORD_RESET_FROM=AlbaSpace <no-reply@albaspace.com.tr>
```

## 3. Apply the D1 migration

From a GitHub Codespace or another environment with Wrangler authenticated to the same Cloudflare account:

```bash
cd cloudflare-worker
wrangler d1 execute albaspace-db --remote --file migrations/0008_password_reset.sql
```

This only adds new tables; it does not replace or delete the existing users/sessions data.

## 4. Use the password-reset entrypoint

The Worker entrypoint for this feature is:

```text
worker-auth.reset.index.js
```

The updated `wrangler.toml.example` in this branch already points to it.

If your real `wrangler.toml` is not tracked by Git, update only this line:

```toml
main = "worker-auth.reset.index.js"
```

Keep the existing D1/R2/Durable Object bindings unchanged.

## 5. Deploy

```bash
cd cloudflare-worker
wrangler deploy
```

The wrapper delegates every existing route and scheduled task to the current `worker-auth.index.js`; it only intercepts the two password-reset routes.

## 6. Verification checklist

1. Open `/forgot-password.html`.
2. Enter a real email/password AlbaSpace account.
3. Confirm the UI always shows the generic success message.
4. Confirm the message arrives from the verified AlbaSpace domain.
5. Open the reset link from the email.
6. Set a password of at least 8 characters.
7. Confirm the same link cannot be used a second time.
8. Confirm the old password no longer works.
9. Confirm existing sessions for that account have been invalidated.
10. Repeat once from `/eng/forgot-password.html` and `/rus/forgot-password.html` to verify localization.

## Notes

Google-only accounts deliberately do not receive a password-reset email because they do not have an AlbaSpace password. The endpoint still returns the same generic response so it does not reveal how an email address is registered.
