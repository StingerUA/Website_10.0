# AR Restaurant Next · v0.1

Отдельный прототип ресторана для проверки размещения блюд на реальной поверхности и управления жестами.

## Маршруты и границы изменений

- `/ar-restaurant-next/` — турецкий интерфейс, обязательная проверка сессии через существующий `/me`.
- `/rus/ar-restaurant-next/` — русский интерфейс, гостевой доступ.
- Исходные `/ar-restaurant/`, `/rus/ar-restaurant/`, их JS/CSS, модели, постеры и основная навигация не изменены.
- Ветка `feature/ar-restaurant-next` не публикуется существующим Pages workflow: он запускается для `main`. До отдельного решения о слиянии новые маршруты на production недоступны.

Проверка сессии — ограничение интерфейса, как у исходного ресторана. Статические модели остаются публичными. Подтверждённые сервером быстрые аккаунты без email допускаются; токен из URL переносится в существующее хранилище и удаляется из адреса. Глобальный `fetch` не подменяется.

## Краткий аудит исходной версии

Исходная страница использует локальный `model-viewer.min.js`, `restaurant-model-viewer.js` как адаптер авторизации/масштаба и `restaurant-model-viewer-core.js` для меню и отображения. В коде присутствует отключённая A-Frame сцена с виртуальным столом (`IS_DESKTOP_SCENE = false`). В Next она не переносится.

Все 10 блюд сохранены: 3 мясных, 3 десерта, суп и 3 напитка. `catalog.mjs` содержит снимок исходных названий, описаний, цен, категорий, путей, ориентации, экспозиции и масштаба. Напитки сохраняют масштаб `0.5`; у супа используется уже подготовленная геометрия. Автоматической нормализации всех моделей к одинаковому размеру нет. Донер загружается как многофайловый glTF; для сжатых GLB подключён Draco. Тест сравнивает каталог с исходным кодом и проверяет существование ресурсов и glTF sidecar-файлов.

## Доступные режимы

| Режим | Когда используется | Поведение |
| --- | --- | --- |
| WebXR AR | Браузер предоставляет `immersive-ar`, `hit-test` и DOM overlay | Сканирование, индикатор горизонтальной поверхности, размещение только по нажатию, перемещение по выбранной плоскости, масштаб и поворот |
| Нативный AR | Доступен Scene Viewer или Quick Look, а собственная XR-сессия недоступна | Открывается системный просмотрщик; управление определяется им |
| Камера и руки | Пользователь отдельно включает экспериментальный режим | Локальная обработка изображения, курсор указательного пальца, pinch для захвата, две руки для масштаба/поворота; блюдо не закреплено в пространстве |
| Обычный 3D | Начальный режим и устройства без AR | Просмотр и вращение блюда, меню, понятное сообщение при недоступном AR |

### Размещение и управление

1. Выбрать блюдо, нажать «Поставить на стол» и разрешить AR.
2. Медленно направлять камеру на освещённую горизонтальную поверхность. После стабильного hit-test появляется готовый индикатор.
3. Нажать «Разместить здесь» или коснуться свободной области сцены. Автоматического размещения нет.
4. Перетаскивать блюдо одним пальцем; двумя пальцами менять размер и поворот. Доступны также ползунки и сброс.
5. «Другое место» снова включает сканирование. Сброс reference space также требует нового размещения.

Позиция блюда хранится отдельно от reticle. После размещения следующие hit-test результаты не перемещают блюдо. При потере tracking взаимодействие останавливается, объект временно скрывается. Фильтр принимает направленные вверх поверхности с наклоном до 20° и требует 220 мс стабильных попаданий в пределах 4 см. Это поиск геометрической поверхности, а не распознавание именно стола.

В XR руки работают только при наличии `XRHand` у устройства. Захват выполняется pinch рядом с блюдом; две руки меняют масштаб и поворот. Обычный смартфон может не предоставлять такие input sources. Камера для MediaPipe не запускается параллельно с XR: доступ к кадрам AR-камеры не гарантирован браузерами.

### Режим камеры

Разрешение запрашивается после нажатия кнопки. MediaPipe обрабатывает кадры в Worker на устройстве, код приложения не отправляет их на сервер. При первом запуске загружаются библиотека, WASM и модель распознавания. Есть переключение камеры, учёт зеркальности и обрезки видео, сглаживание, гистерезис pinch и сброс захвата при потере руки. Поток, Worker и цикл обработки завершаются при выходе или скрытии страницы.

## Файлы и зависимости

| Файл | Назначение |
| --- | --- |
| `assets/js/restaurant-next/app.mjs` | Меню, состояния интерфейса, выбор режима, обработка отказов |
| `catalog.mjs`, `i18n.mjs`, `auth.mjs`, `config.mjs` | Каталог, тексты TR/RU, сессия, настройки |
| `xr-session.mjs` | Разрешения XR, reference space, hit-test и освобождение ресурсов |
| `scene.mjs` | Three.js, загрузка моделей, reticle, размещение и жесты |
| `math.mjs` | Фильтр поверхности, pinch, преобразование координат и жестов |
| `hands.mjs`, `hand-worker.js` | Камера, жизненный цикл распознавания и MediaPipe |
| `assets/css/restaurant-next/app.css` | Изолированные адаптивные стили |

Используются существующий локальный model-viewer, Three.js **0.164.1** и его Draco decoder с jsDelivr, MediaPipe Tasks Vision **0.10.14**, модель Hand Landmarker **float16/1** из Google Storage. Версии URL закреплены. Первый запуск требует доступа к этим ресурсам; offline-режим не реализован. Камера и WebXR требуют HTTPS либо доверенного localhost.

Ограничения нагрузки: pixel ratio до 1.5, камера до 640×480 и 30 fps, отправка кадров распознавания до 20 fps, не более одного кадра в обработке, один Draco worker. Это ограничения конфигурации, а не подтверждённая производительность на телефоне.

## AR LAB

Показывает поддержку WebXR, фактическое состояние hit-test и XR hand input, режим, FPS собственного renderer, количество рук, жест, выбранное блюдо, исходный/пользовательский масштаб, draw calls, треугольники, текстуры и время inference. В обычном model-viewer собственный FPS не измеряется. Возможности, которые ещё не проверялись внутри XR-сессии, отмечаются `not tested`.

Для скрытия кнопки в конкретном запуске добавить `?lab=0`. Для отключения диагностики и её таймера установить `CONFIG.lab = false`.

## Воспроизводимая проверка

```sh
npm ci
node --test scripts/restaurant-next.test.mjs
npx playwright install --with-deps chromium
node scripts/restaurant-next.browser.mjs
```

Workflow `Restaurant Next` использует Ubuntu 22.04 и Node 20 для совместимости с Playwright 1.42 из существующего lockfile. Основные зависимости сайта не обновляются.

- 14 тестов Node: устойчивость поверхности, потеря tracking, pinch, смена пальцев/рук без скачков, координаты камеры, возможности, авторизация, запуск/отмена/очистка XR, reset reference space, паритет каталога, ресурсы и независимость страниц.
- Браузерная проверка: настоящая загрузка всех 10 моделей через model-viewer и Three.js, меню, отказ AR, запуск MediaPipe на синтетическом видеопотоке, освобождение камеры, TR gate и гостевой RU, загрузка исходных страниц.
- Синтетическое воспроизведение кадров сцены: запрет размещения до стабильного попадания и до нажатия, неизменность координат после движения камеры, потеря/восстановление tracking, смена состава жеста без скачка.
- Результаты и снимки интерфейса: артефакт `restaurant-next-checks` соответствующего запуска GitHub Actions. `report.json` явно содержит `hardwareARTested: false`.

Для просмотра ветки локально:

```sh
git switch feature/ar-restaurant-next
python3 -m http.server 4173 --bind 0.0.0.0
```

Открыть `http://localhost:4173/rus/ar-restaurant-next/` на том же компьютере. Для телефона нужен HTTPS-адрес этого сервера, например forwarded URL собственного Codespace. Обычный HTTP по IP компьютера не подходит для камеры/WebXR. Scene Viewer должен иметь сетевой доступ к URL модели; закрытая авторизацией forwarding-ссылка может не подойти.

## Что ещё проверить на устройствах перед публикацией

- [ ] Android + ARCore + Chrome: разрешение/отказ, горизонтальная поверхность, отсутствие автоматического размещения, стабильность при обходе вокруг блюда, одно/двухпальцевые жесты, rescan и выход.
- [ ] Потеря tracking, переключение приложения, поворот экрана, повторный запуск, смена блюда во время сканирования и после размещения.
- [ ] iPhone/Safari: переход в Quick Look, реальный размер блюда и возврат на страницу.
- [ ] Устройство без WebXR/ARCore: работающее меню и обычный 3D, понятный fallback.
- [ ] Камера: реальные руки, pinch, две руки, фронтальная/задняя камера, плохое освещение, отказ разрешения и прекращение индикатора камеры после выхода.
- [ ] TR: существующая обычная и быстрая учётная запись; RU: гостевой вход. Реальный backend не заменять моками при этой проверке.
- [ ] Физический масштаб всех блюд и производительность на среднем телефоне в течение нескольких минут.

У v0.1 нет постоянных anchors между сессиями, сохранения расстановки, occlusion, распознавания границ стола или нескольких блюд одновременно. Качество пространственной фиксации зависит от tracking устройства. Нативные просмотрщики не сохраняют наш DOM-интерфейс/жесты и могут иначе применять освещение и runtime-масштаб. Синтетические тесты не подтверждают качество AR и распознавания реальных рук.
